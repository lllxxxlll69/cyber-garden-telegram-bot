# Telegram PDF-сервер Cyber Garden

Отдельный локальный процесс на Node.js 22+. Регистрация и вход в браузере, серверные сессии, привязка Telegram одноразовым кодом, PDF на русском и очередь доставки. Публичный сервер и webhook Telegram не нужны: бот получает команды через long polling [Telegram Bot API](https://core.telegram.org/bots/api).

## Запуск на Windows

Из корня репозитория:

```powershell
cd server
npm ci
Copy-Item .env.example .env
notepad .env
# Вставьте TELEGRAM_BOT_TOKEN, выданный @BotFather
npm start
```

Откройте http://127.0.0.1:8787. Создайте аккаунт с паролем от 12 символов. Нажмите «Получить код входа» и отправьте показанную команду `/login КОД` своему боту в личном чате. Затем загрузите `example-report.json`: PDF появится в Telegram в течение 15 секунд, если Telegram доступен. Без токена можно работать с аккаунтами, загружать JSON и скачивать PDF в браузере.

Сервер должен оставаться запущенным для приёма команд и отправки. Один токен бота используется только одним poller; ранее настроенный Telegram webhook нужно предварительно отключить. Реальная доставка требует вашего токена и соединения с Telegram; автоматические тесты используют подменённый транспорт и не отправляют сообщения.

## Автоматическая доставка из приложения

В настольном приложении откройте «Подключения» и включите «Добавлять JSON к отчётам в Telegram», чтобы получать оба файла при ручной и автоматической отправке из приложения. Кнопка «Скачать JSON» в самом отчёте работает и без подключения к боту.

Для отправки по кнопке настройка webhook не требуется. В приложении нажмите **Telegram**, войдите в аккаунт этого сервера и подключите бот с помощью одноразового кода, если он ещё не привязан. После проверки нажмите **Отправить в Telegram** в отчёте или откройте отчёт из истории. Приложение проверяет наличие активной Telegram-сессии и сохраняет отчёт в очередь PDF-доставки. Сессия входа сохраняется защищённо; после истечения нужно войти снова. Ниже описана отдельная автоматическая отправка через блок сценария.

1. В локальной странице создайте токен интеграции. Это отдельная от браузера сессия с полным доступом к вашему аккаунту через API. Сохраните токен: он отображается только при создании.
2. В Cyber Garden откройте «Подключения», выберите доставку на webhook.
3. Адрес: `http://127.0.0.1:8787/api/reports`. В поле токена webhook вставьте полученный токен. Адрес с другим портом соответствует `PORT` сервера.
4. Добавьте блок HTTP webhook после анализаторов и запустите проверку.

Приложение хранит этот токен через Electron safeStorage отдельно от ключа модели. После истечения или отзыва API-сессии создайте новый токен и обновите настройки приложения. HTTP 201 означает сохранение отчёта и постановку в очередь, а не подтверждение получения Telegram.

Для CLI:

```powershell
$env:REPORT_WEBHOOK = 'http://127.0.0.1:8787/api/reports'
$env:REPORT_WEBHOOK_KEY = '<токен интеграции>'
node garden/cli.cjs ../cyber-garden-testbed ../cyber-garden-testbed/workflow.json ../cyber-garden-testbed/advisories.json
```

Команду CLI запускайте из корня репозитория; в сценарии нужен блок notify. Можно загружать JSON полного результата CLI или тело `security.report`: сервер принимает поле `findings`, остальные служебные поля не требуются. Содержимое исходников и значения секретов сервер специально не добавляет в PDF.

## Команды бота

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Справка |
| `/login КОД` | Обмен одноразового кода на Telegram-сессию |
| `/reports` | Последние 10 отчётов вашего аккаунта |
| `/report` | PDF последнего отчёта |
| `/report ID` | PDF определённого отчёта |
| `/json [ID]` | JSON выбранного отчёта или последнего без ID |
| `/sessions` | Активные сессии |
| `/logout` | Отзыв сессии текущего Telegram-чата |

Вход работает только в личном чате. Один Telegram-чат одновременно связан с одним аккаунтом. Новый вход заменяет прежнюю привязку чата. Каждый новый отчёт отправляется во все активные Telegram-сессии владельца на момент сохранения. Старые отчёты доступны через `/report`, повторной автоматической рассылки после привязки нет.

## Сессии и хранение

- Пароли: scrypt с индивидуальной случайной солью. Сервер хранит хеши токенов сессий и кодов, без исходных значений.
- Web/API-сессии: случайный токен 256 бит. Браузер использует HttpOnly / SameSite=Strict cookie, интеграции — `Authorization: Bearer TOKEN`. Токены в URL не принимаются.
- По умолчанию все сессии действуют 168 часов, без автоматического продления. `SESSION_HOURS`: 1-720. Код привязки действует 5 минут и зависит от исходной сессии; повторное создание аннулирует предыдущий код аккаунта.
- Сессии можно отзывать по отдельности на странице. Выход из браузера отзывает только текущую сессию. API и Telegram-сессии завершаются отдельно.
- Проверки Host/Origin, запрет cross-site запросов, лимиты попыток входа, размер JSON до 2 МБ и до 500 находок на отчёт.
- `server/data/store.json` хранит аккаунты, сессии, отчёты, очередь и offset Telegram. Данные переживают штатный перезапуск. Транзакции сериализованы, файл записывается через временный файл, fsync и rename. Доступ к каталогу ограничивайте средствами ОС, особенно на Windows.
- `server.lock` предотвращает запуск двух процессов с одним каталогом. После аварийного завершения удаляйте его только убедившись, что старый процесс остановлен. Повреждённое хранилище не заменяется пустым автоматически.
- Очередь повторяет неудачную отправку до 8 попыток с увеличением интервала. Статусы видны на странице после «Обновить». При отзыве/истечении целевой Telegram-сессии ожидающие отправки отменяются; уже начатую отправку отозвать нельзя.
- Доставка имеет семантику at least once: при аварии между ответом Telegram и сохранением статуса возможно повторное сообщение. Необработанная команда повторяется при следующем polling; отправленный одноразовый код уже нельзя использовать повторно.

Каталог данных и `.env` исключены из Git. Для резервной копии остановите сервер и скопируйте `store.json`. Никаких настоящих аккаунтов или паролей по умолчанию не создаётся.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | `ok`, `telegramConfigured` (токен настроен), `telegramConnected` (polling Telegram подключён) |
| POST | `/api/register` | `{ "login": "user", "password": "..." }` |
| POST | `/api/login` | Та же структура; возвращает токен и устанавливает cookie |
| GET | `/api/me` | ID текущей и список активных сессий |
| POST | `/api/sessions` | Создать отдельную API-сессию |
| DELETE | `/api/sessions/ID` | Отозвать свою сессию |
| POST | `/api/logout` | Завершить текущую сессию |
| POST | `/api/telegram/code` | Получить одноразовый код привязки |
| POST | `/api/reports` | Сохранить `{ "title": "...", "findings": [...] }` и поставить доставку в очередь |
| GET | `/api/reports` | Последние 50 отчётов аккаунта |
| GET | `/api/reports/ID/pdf` | Скачать PDF с проверкой владельца |
| GET | `/api/deliveries` | Последние 100 доставок аккаунта |

Все `/api/*`, кроме регистрации и входа, требуют сессию. Тело запросов с данными: `application/json`. Пример находок — `example-report.json`.

## Перенос на БД

`store.cjs` — единственный файловый адаптер. HTTP и Telegram используют общий `ReportService`. Контракт репозитория: `read(fn)` передаёт отделённый снимок, `transaction(fn)` атомарно фиксирует синхронный callback или откатывает его. Для первого переноса можно реализовать этот контракт поверх SQLite/PostgreSQL с транзакцией и блокировкой строки состояния, внедрив другой репозиторий в `index.cjs`.

Для нормализованной БД следующая структура: users (unique login), sessions (user_id, token_hash, expires), pairing_codes (unique hash, session_id, expires), reports (user_id), findings (report_id), deliveries (report_id, session_id), bot_state и login_attempts. На больших объёмах замените операции над снимком методами репозитория для каждой сущности и захватом заданий очереди. Текущий JSON-адаптер целиком держит данные в памяти, не предназначен для нескольких серверов и не выполняет автоматическую очистку истории отчётов.

По умолчанию локальный режим слушает loopback. Для Android в общей доверенной Wi-Fi сети поддерживается `HOST=0.0.0.0` с явным `ALLOWED_HOSTS` (IPv4 компьютера); подробности, API рабочего пространства и сборка APK — в [Android README](https://github.com/lllxxxlll69/cyber-garden-mobile). Для удалённого развёртывания отдельно настройте HTTPS, разрешённые Host/Origin, доверенный reverse proxy и Secure cookie; установка `COOKIE_SECURE=true` сама по себе не добавляет HTTPS.

## Проверки

```powershell
cd server
npm test
```

Тесты проверяют сохранение и отзыв сессий, истечение кодов и сессий, одноразовость, изоляцию аккаунтов, throttling, атомарность, HTTP и cookie, команды Telegram и повтор доставки, многостраничные PDF. Из корня этого репозитория: `node --test garden/test.cjs garden/github.test.cjs garden/custom.test.cjs`.

Проверки Electron доступны в [основном репозитории](https://github.com/Maxuttta/hackgarden2026): `npm run smoke:reports` и `npm run smoke:mobile`. Они используют временные данные и не отправляют настоящих сообщений.

PDF создаётся [PDFKit](https://pdfkit.org/docs/text.html) со встроенным TTF-шрифтом JetBrains Mono из [официального репозитория](https://github.com/JetBrains/JetBrainsMono/tree/master/fonts/ttf). Лицензия: `assets/fonts/JetBrainsMono-OFL.txt`.
